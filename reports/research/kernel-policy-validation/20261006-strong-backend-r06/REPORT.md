# R06：同精度完整前馈模块的强基线与剩余策略空间

## 决策摘要

R06预实验已完成。建议暂停把当前“复杂内核选择器/跨GPU预测器”作为方法论文主线，不再直接追加预测模型或跨GPU大规模采样。
这不是断言所有内核选择问题都已解决，而是在当前六个形状、单卡、四类候选和固定输入精度契约下，强编译器基线已经覆盖主要收益：两个独立测试进程的六个图模式模块，全部由整模块编译版本取得实测最低中位数。普通模式固定编译器平均观测损失2.309%，一份校准后冻结的简单表为1.762%，尚未证明复杂选择算法的必要性。

重要区别：这些加速来自现有PyTorch编译器对整个模块的优化，不是本轮新写了一个更快的CUDA内核。旧V4/V7设备代码和生产库完全未改。

本轮模块：RMSNorm -> BF16输入投影 -> SwiGLU -> BF16下投影 -> 残差相加。
不同于R03/R04的LayerNorm及FP32下投影，不能把跨批绝对时间差当作本轮优化收益。

共同精度契约：输入/权重BF16；RMSNorm统计FP32，eps=1e-6；归一化输出显式舍入BF16；上投影BF16乘法/FP32结果；SwiGLU FP32；激活在下投影前显式舍入BF16；下投影BF16乘法/FP32结果；残差和最终输出FP32。
纯PyTorch路径使用torch.mm(...,out_dtype=torch.float32)，本轮真机验证该接口可用。FP32 matmul精度设highest、TF32关闭、BF16 reduced precision reduction关闭。原生库函数调用仍使用原有cuBLAS契约。

参考计算用FP64，并保留同样的BF16边界舍入。预先固定rtol=0.02、atol=0.01和relative L2<=0.003，不因结果放宽。所有正式候选检查通过；不是逐位等价或模型质量保证。

## 2. 候选、模式、工作负载

| 名称 | 完整模块实现 |
|---|---|
| torch_packed | 功能式PyTorch，打包上投影矩阵、显式SwiGLU和下投影 |
| cublas_v4 | 相同PyTorch前后处理，核心换为已有cuBLAS V4 |
| custom_v7 | 相同前后处理，核心换为已有融合WMMA V7 |
| inductor | 将纯PyTorch整个模块以fullgraph=True、dynamic=False、max-autotune-no-cudagraphs编译 |

主比较的两种部署方式：普通逐次提交、显式单次完整模块CUDA Graph重放。图模式双方均捕获整个模块，不拿某一方的图模式与另一方的普通模式计算加速比。
启用最大调优配置不等于每一个矩阵乘都变为Triton：实测编译器计数多数形状仍有两次extern调用；这不是计算图中断或整个模块退回eager。

六个预注册形状M,K,N：16,64,64；32,128,256；128,512,512；1,1536,8960；16,1536,8960；128,1536,8960。
后三者的K1536和N8960来自Qwen2.5-1.5B官方配置，M是实验选值。合成随机输入、按fan-in缩放的随机权重，没有下载checkpoint，不是完整Qwen推理。
来源：https://huggingface.co/Qwen/Qwen2.5-1.5B/blob/main/config.json

M1不支持V7，在覆盖表保留并标注不支持；固定/简单策略回退V4。其余五个形状四个候选，M1三个候选，所以每个进程46行候选汇总，而非删除M1后宣称全覆盖。

## 3. 校准与独立测试

两次calibration，data_seed=6061，order_seed=6071/6072；生成冻结表后，再运行两次test，data_seed=6161，order_seed=6171/6172。
每组6轮、每轮每候选24次，候选位置和AB/BA次数严格均衡；组顺序随机。每个候选先预热和检查数值；编译、图构建不进入稳态样本。

冻结表SHA256：7db25b62c6df0d725b3ac20eb1fff1209546bab9cfed004d181cb24b810677b6。
规则：默认编译器；只有其他候选在两次校准中都至少快1.05倍才切换。最终仅32x128x256普通模式切换V7，其余11个case/mode保留编译器。两次test读取相同文件；收集器重新从calibration数据得到相同选择表。

编译计数验证：24个主实验case编译各增加1个unique_graphs，graph_break增加0。没有开启suppress_errors。编译/调优有实际成本，绝不是免费的“固定后端”：cal01与cal02总过程耗时分别约13.645和6.498秒；缓存复用且部分配置仍做坐标调优，因此这些不是统一的冷编译时间或在线选择器成本。每次first-call/setup已留在原始元数据。

## 5. 策略空间，而不是命中率故事

指标 = 选定候选的完整模块中位数 / 同条件合法候选的最低中位数 - 1。
这是有限候选的观测最小值，不是噪声无关oracle。均匀平均六个形状乘两个进程，不代表真实流量加权。

| 策略 | 普通模式平均损失 | 普通模式最坏损失 | 图模式平均损失 |
|---|---:|---:|---:|
| 固定V4库路径 | 5.711% | 9.835% | 64.446% |
| 固定整模块编译器 | 2.309% | 8.793% | 0.000% |
| 原V11静态区域选择 | 4.232% | 9.835% | 66.355% |
| 校准后冻结的简单表 | 1.762% | 8.793% | 0.000% |

图模式0%只表示本批全部选择与实测最小中位数一致，没有证明未见形状/新GPU始终如此。
普通模式仍有微小控制点上的收益、主机提交与分配影响，不声称所有问题消失；但当前简单策略剩余平均空间小，尚无足够证据投入更复杂预测器。
旧规则的大图模式损失不是某个单内核突然退化，而是参照候选集合新增了整模块编译器；不能与R03/R04只含V4/V7的损失表直接比较。

## 6. 托管图模式的补充核验

独立managed01诊断比较max-autotune托管图，与max-autotune-no-cudagraphs加显式完整模块图。

每个形状、每种调用方式采集3次分析器调用，12份时间线均观察到3次实际图启动API；图确实发生。

## 8. 去留决定与限制

当前停止升级“从V4/V7切换发展复杂选择器”这个方法论文假设。保留所有代码和负结果，不删除科研分支，不修改主分支，不将这些实验包装为新算法论文。
若以后出现真实业务权重、更多强候选或严格部署约束下的稳定较大剩余损失，才重新开启该选题；现在不通过新增预测模型掩盖强基线已经有效这一事实。

限制：单张未锁频的笔记本GPU、同会话独立进程、六个固定形状、合成权重、静态图可捕获范围、无真实到达流量、无未见形状或跨GPU测试。BF16边界舍入误差在预声明范围内，但不等于语言模型质量评估。没有测完整策略查询开销、冷编译全成本或生命周期净收益；结论是当前研究投入优先级判断，不是最优性证明。
